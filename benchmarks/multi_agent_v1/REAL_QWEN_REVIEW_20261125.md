## 人工复核

逐条核对报告结论的全部实质内容、原文和题目范围。原文与题目约束共同明确支持的发现为“完整”。原文支持其中一部分但添加了未经支持的流程、条件、评价或否定结论，归为“部分”。原文真实但偏离研究问题，归为“无关”。这项复核只覆盖固定合成材料内的证据支持。

| 行 | 按结论输出顺序 | 复核依据 |
|---|---|---|
| RAG A | 无可复核结论 | 模型在已有局部材料时仍选择空结论 |
| RAG B | 完整、部分、部分、部分、部分、部分 | ① 已有 PostgreSQL 与题目优先复用约束直接相符。② 独立服务并不能直接证明不符合复用要求。③ 考虑已有集群尚非确认符合。④ 压测摘录不能推出运维监控与故障恢复。⑤ 轮值摘录不包括监控与恢复流程。⑥ 值班摘录不支持检索质量测量判断 |
| RAG C | 完整、部分、部分、部分、部分、部分 | ① 同上。② 独立服务资料未提到额外权限。③ 考虑已有集群尚非确认符合。④ 原文写了压测安排，未交代量化扩展边界。⑤ 后续压测安排已覆盖“待验”信息，无法推出整个维度没有覆盖。⑥ 原文要求验证资源隔离，未断言没有测量标准 |
| 企业内部多文档 | 完整、完整、完整、无关 | 入库审核和登记、备份恢复及团队交接均由手册直接支持。会议纪要模板抽取正确，但与任务无关 |
| 无生产实测 | 完整、完整、完整、完整 | 压测排期和联调简报均直接说明未生产实测或未记录数据，报告没有给出虚构吞吐值。个别 Worker 把“未测量”算作覆盖，最终状态仍为证据不足 |

`facts_verified` 均为 `false`。引用校验通过只说明来源和摘录匹配。模型仍可能过度扩大范围、误判已覆盖维度，或在原文后加上未经支持的推论。

## 最终代码 RAG 复查

可比运行的 C 将 PgVector 的运维误判为覆盖，因此没有查到对应手册。最终修订在 Review 触发补查时增加词项提示。具名候选的原文没有出现某个请求维度的标签时，优先用“候选名 + 维度”搜索。词项只影响检索调度，充分性判断仍走评估。此逻辑对单 Agent、关闭补查的 B 和自然语言主题任务不生效。

沿用原题、原资料、模型和预算复查 C 一次。三个子任务并行首查。PgVector 定向补查获新增运维材料，Milvus 补查无新增摘录，Elasticsearch 保留首轮结果。主任务完成部分报告，关键材料 **4/4**、维度 **12/12**、程序校验 **7/7**，实测 8 次请求、9,769 Token、35.37 秒。[最终代码 RAG 复查记录](real_qwen_rag_recheck_20261125.json)

七条结论的严格人工复核为一条完整相关、六条部分。第一条“沿用现有 PostgreSQL”有直接证据且符合题目优先复用的范围。② 独立服务的要求并未证明无法复用。③ 考虑已有集群与确认符合仍有差距。④ 和 ⑤ 的压测计划能支持“待测”，资料未说明是否制定标准。⑥ 原文只写资源隔离需验证。⑦ 明确待确认的是夜间告警、交接演练等事项，结论扩写成告警响应机制。RAG 复查覆盖增加，选型建议的可靠性仍需要人工把关。
